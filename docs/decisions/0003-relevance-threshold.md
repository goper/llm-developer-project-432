# 0003. Порог релевантности 0.82

Дата: 2026-11-09. Статус: принято.

## Как калибровали

Пять выданных документов проиндексированы моделью `intfloat/multilingual-e5-small` с префиксами
`query: ` / `passage: `. Для запросов двух видов сняли косинусную близость трёх лучших фрагментов.

| Запрос | Вид | Лучший | 2-й | 3-й |
| --- | --- | --- | --- | --- |
| Какая мощность у блендера | верный | 0.872 | 0.842 | 0.839 |
| мотор 800 Вт | верный | 0.841 | 0.827 | 0.816 |
| гарантия на блендер | верный | 0.861 | 0.841 | 0.835 |
| объём чайника | верный | 0.855 | 0.800 | 0.794 |
| цена BLD-800 | верный | 0.866 | 0.855 | 0.827 |
| KTL-1700 | артикул | 0.862 | 0.833 | 0.803 |
| рецепт борща | мусор | 0.809 | 0.801 | 0.800 |
| курс доллара на завтра | мусор | 0.793 | 0.786 | 0.785 |
| ремонт автомобиля | мусор | 0.817 | 0.814 | 0.795 |

## Решение

`RELEVANCE_THRESHOLD=0.82`. У e5 близости сжаты в узкую полосу (0.78–0.88), поэтому «типичные» пороги
0.5–0.7 пропускают всё подряд. Верхний результат верных запросов не ниже 0.841, верхний результат
мусорных — не выше 0.817. 0.82 лежит между ними: мусорные запросы не дают ни одного фрагмента,
верные теряют только хвост.

## Оговорки

- Набор маленький (пять документов), запас между классами — около 0.02. На большом наборе
  (`data/bulk/`) порог надо перепроверить.
- Порог относится к векторной части. В гибридном поиске фрагмент, найденный по словам (артикул),
  проходит и при низкой близости: иначе гибрид терял бы как раз то, ради чего он нужен.
- Таблица `kettle_spec.xlsx` целиком влезает в один фрагмент, поэтому на этих данных поиск по смыслу
  находит артикул «KTL-1700» (0.862) — он попадает вместе с заголовками колонок. На спецификации
  из многих фрагментов это не так; тест `tests/test_repositories.py` проверяет различие режимов
  на векторах, заданных руками.
